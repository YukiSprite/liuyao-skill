# 输入与计算约定

## 1. 规范化输入

用户用自然语言提供信息即可，由调用 skill 的模型生成此结构。

```json
{
  "question": "这笔款项能否在本月底前收回？",
  "context": "对方曾承诺付款，但尚未到账。",
  "tosses": [1, 1, 0, 2, 1, 3],
  "input_mode": "back_count",
  "order": "first_to_sixth",
  "time": {
    "kind": "civil",
    "at": "2021-10-13T09:14:00",
    "timezone": "Asia/Shanghai",
    "day_boundary": "midnight"
  },
  "focus": "妻财"
}
```

上述问题为演示编写，日期、投币序列来自教程示例，不是用户的一次实际占问。

| 字段 | 要求 |
|---|---|
| question | 必填，非空问题文字；保留用户所问对象与时间范围 |
| context | 可选，用户提供的现实背景文字，不能补编 |
| tosses | 必填，恰好六个整数 |
| input_mode | 必填，`back_count`、`front_count`、`line_values` 之一 |
| order | 默认 `first_to_sixth`，表示第 1→6 次投掷；`top_to_bottom` 表示从上爻向初爻抄写 |
| time | 可省略，等同 unknown；不能省略后偷偷改用现在 |
| focus | 可选：父母、兄弟、妻财、官鬼、子孙、世爻、应爻；取舍依据在分析中说明 |

原始计数与输入顺序存于 `input`，转换后的 6—9 爻值存于 `normalized_values_bottom_up`。

## 2. 面数和爻值

| 背面数 | 对应正面数 | 规范爻值 | 本卦 | 是否发动 | 变后 |
|---|---|---|---|---|---|
| 0 | 3 | 6／老阴 | 阴 | 是 | 阳 |
| 1 | 2 | 7／少阳 | 阳 | 否 | 阳 |
| 2 | 1 | 8／少阴 | 阴 | 否 | 阴 |
| 3 | 0 | 9／老阳 | 阳 | 是 | 阴 |

`front_count` 是按本表与背面计数互补的正面数，不是另一流派的独立约定。若用户使用其他约定，应先确认四种结果分别对应的老阴、少阳、少阴、老阳，然后显式转为 `line_values`；在最终记录中注明实际约定。

四次、五次或七次投掷不能自动补足或截断。六个数字中混用 0—3 与 6—9、输入小数或布尔值，程序均拒绝。

## 3. 时间模式

### civil：准确公历时刻

至少包含时分。`at` 可自带 UTC 偏移；若自带偏移，转换至 `timezone` 的当地时间后确定日时。无偏移则按所选 IANA 时区解释。夏令时跳过或重复的模糊当地时间要求补偏移。

支持 1900—2100 年。使用随附的 lunar_python 1.4.8：

- 年柱以立春交接时刻为界；月柱按“节”交接时刻，不按公历月或农历初一。
- 节气比较使用真实时刻转换后的 UTC+8 时间，与库的节气时间基准一致。
- 日柱按所选当地民用日期计算；`midnight` 零点换日，`zi23` 23 点换日。
- 时支按当地钟表时间；本 skill 的时干约定跟随所选日柱，避免混用另一种晚子时日干。这是显式工程约定，不声称为唯一传统口径。
- 不做经度或真太阳时校正；用户要求该模式时需说明本版尚不支持。

### now：用户明确表示刚摇完或要求使用现在

```json
{"kind": "now", "timezone": "Asia/Shanghai", "day_boundary": "midnight"}
```

程序读取执行时刻并保存实际时间。复盘时使用已保存的实际 `at` 转成 civil 输入，不重新运行 now 来替换旧卦时间。

### manual：已有月支和日干支

```json
{"kind": "manual", "month_branch": "戌", "day_ganzhi": "甲午", "source": "用户提供的排盘记录"}
```

只用于用户明确提供的月支、日干支，或已经核验的外部记录。程序检查日干支是否属于六十甲子，然后据日干排六神、据日柱计算旬空；不伪造年柱、时柱或公历日期。此处月支必须是排盘所用的节令月支，不能由“农历八月”直接猜成一个地支。

### unknown：时间缺失

```json
{"kind": "unknown"}
```

本变卦、世应、纳甲、六亲、伏神仍可计算；六神、旬空、日月关系保持缺失。基于这些静态事实作有限分析，并询问原起卦时间。仅给公历日期且不能确定时分时也可先走此模式，不应估填时刻。

## 4. 输出数据的方向和边界

| 输出字段 | 解释 |
|---|---|
| lines_bottom_up | 初爻→上爻；每行有爻值、阴阳、纳甲、六亲、六神、世应、伏神和时间标记 |
| original | 本卦名称、所属宫和世应；其宫五行是全部六亲的参照 |
| changed | 无动爻时为 null；有动爻时包括变卦名称和全盘布局 |
| change | 每条原动爻的本位化出；静爻此字段为 null |
| layout_bottom_up | 变卦整体排布，不能将每一行都当作独立化出并作用其他爻 |
| focus_candidates | 符合所选类别的本卦候选；本卦缺该类时列伏神；没有按旺衰擅自定用 |
| nominal_edges | 原明动爻到其他本卦爻，以及本位变爻到原动爻的名义关系；不含自动推定的暗动 |
| flags | 临日月、旬空、月冲、日冲等事实标记；不是吉凶结论 |
| text_diagram | 可直接放入等宽代码块的字符卦图；本变卦并排，箭头仅标原动爻，世应仅标本卦 |

`relation(source, target)` 始终按来源 → 对象解释：

- `生`：来源五行生对象。
- `克`：来源五行克对象。
- `被生`：来源被对象所生。例如月支为申、爻支为戌，表示爻土生月金，不是月生爻。
- `被克`：来源被对象所克。
- `比和`：五行相同；`same_branch` 另表是否同一地支。
- `combines` 和 `clashes` 按固定六合、六冲配对独立记录，不能因五行生克关系就删掉冲合事实。

伏神所附爻是位置关系。模型不得因附在动爻旁就自动将伏神判为发动，也不得认为伏藏便必然无用。

## 5. 文件输出

默认标准输出 JSON，其中 `text_diagram` 为完整字符卦图。指定新目录时生成 `input.json`、`chart.json`、`chart.md`、`diagram.txt`，不覆盖旧目录。`chart.md` 已嵌入字符卦图，`diagram.txt` 可单独复制分享。模型解释完成后可按用户保存意愿另写 `analysis.md`。`chart_id` 标识一次规范输入及计算结果；不能把它理解为预测置信度。
