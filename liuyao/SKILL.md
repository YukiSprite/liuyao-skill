# 六爻排盘与解读

接收用户的具体问题和真实投币结果，调用随附程序得到可复核的卦盘，再依据参考规则解释。回复使用中文，先给明确的占断倾向，再说明卦盘和依据。占断是传统规则下的解释性判断，不写成已证实的现实结果。

## 输入

先读 [输入与计算约定](references/input.md)。通常用户只需给问题、六次结果和起卦时间；不要要求填写内部 JSON。

- 保留问题原意、占问对象及期限；仅在缺失信息会改变取用时追问。例如“考试如何”需要分清成绩、录取还是证书。
- 一次卦有且只有六次投掷，每次三枚硬币。第一次是初爻，在最下方。若用户按卦图从上往下抄写，先按其说明转换顺序。
- 接受每次背面数 0—3、正面数 0—3、六个爻值 6—9，或六组三枚正反面文字。文字结果先依明确约定转换为计数。
- 本教程约定：背面数 0/1/2/3 分别为老阴/少阳/少阴/老阳。“花面”“字面”“正面”不自动等于背面；不清楚时用一句话确认。用户只有裸串 `110213` 且未说明含义或顺序时，也应确认。会话已确认的约定可沿用。
- 不补掷、不改值、不生成用户没提供的随机结果。本 skill 当前范围是接收用户投币；用户另要求模拟起卦时，说明本版未提供该入口。
- 时间使用原起卦时刻。用户明确说“刚摇完”“按现在”才使用 `time.kind=now`；不得把分析时刻当成旧卦的起卦时刻。未说明时间时可以先输出无时间的卦象，简短询问原起卦时间。
- 默认时区 Asia/Shanghai，零点换日，并在结果注明；用户明确指定 23 点换日则使用 `zi23`。日期没有时分时不要擅自填中午。用户只给已排好的月支、日干支时可用手动模式并注明来源。

## 计算

用 Python 3.9+ 执行本 skill 的 `scripts/paipan.py`，它携带离线历法依赖，不需要联网或 API 密钥。

1. 将用户输入规范化为 [输入结构](references/input.md)，保留原始问题与计数；只做已说明的顺序和面数转换。
2. 根据 [分析规则](references/interpretation.md) 选择用神类别，作为可选 `focus` 传入。若尚不明确，先不传。程序列出候选，不替模型作复杂取舍。
3. 把 JSON 写入临时文件后运行：

```text
python3 -B <skill目录>/scripts/paipan.py --input <输入JSON路径>
```

需要保存结果时指定新的输出目录：

```text
python3 -B <skill目录>/scripts/paipan.py --input <输入JSON路径> --output-dir <新的输出目录>
```

输入含用户文字时使用文件或工具的结构化参数，不拼进可执行的 shell 字符串。输出目录已存在时程序拒绝覆盖；应换一个新目录。

4. 读取程序的 JSON。使用输出目录时读取 `chart.json` 和 `chart.md`。程序返回错误必须先处理，不能把错误输出当成成功结果，也不能绕过程序凭记忆补盘。
5. 检查六个爻位、动爻、世应及时间来源。程序数据数组从初爻到上爻；展示的卦表从上爻到初爻。

`chart.md` 是排盘底稿，不是完成的分析。必须继续完成下面的解释步骤。

## 分析

排盘后读取 [分析规则](references/interpretation.md)。按“取用 → 日月事实 → 动变及作用条件 → 综合解释”处理，并做到：

- 本卦卦宫五行是本卦和变爻六亲的共同参照。不要因变卦所属宫不同而重算变爻六亲。
- 动爻化出与变卦全盘排布不同。只把原动爻的本位变爻当作回头作用来源，不把静爻在变卦中的排布当作又一个动爻。
- 检查用神候选是否多现、是否伏藏，并解释选取依据。有多种合理取法时，选与题意最直接的一种作为主分析，简短说明选择；只有其他取法会改变结论时才补充，不让分支讨论取代主结论。
- `flags`、`month_relation`、`day_relation` 和 `nominal_edges` 记录关系事实，不等于有效作用或吉凶判决。“被生／被克”的方向见输入文档。
- 日冲不自动等于暗动，旬空不自动等于无用，月破不自动等于必败，合不自动等于吉或合绊。
- 每个主要判断对应一个具体爻、关系或输入事实，并给出 R 编号或简短规则出处。不要只写抽象套话。
- 缺少出处或适用条件的条目直接不参与占断，不逐项报告资料缺口。用剩余可用关系作综合判断，给出“偏能／偏不能”“偏顺／偏阻”等主倾向；生克交织时交代判断力度，不用“证据不足以支持判定”“倾向尚不能确定”代替结果。具体收束方式见 R11。
- 应期仅在条件链成立且来源明确时作条件性说明。本版没有通用应期算法，不能由卦名随意指定日期，也不输出未经校准的概率、必然成功或必然灾祸。
- 现实建议必须基于用户提供的现实背景，和卦理解读分开；不把传统取象当成对第三方动机、病情或事实的证据。

资料有疑点或需要解释来源时，读 [来源与核验边界](references/sources.md)。正常使用无需联网检索，也不需每次加载所有原始转录。未收录且未核验的规则直接跳过；用户要求扩充体系时再核验新来源，不能静默混用其他流派。

## 输出

根据问题复杂度组织，通常包含：

1. **对问题的回答：** 开头用“按此卦，我倾向判断……”直接回应用户所问，给出结果方向和判断力度。
2. **起卦记录：** 输入约定、顺序、时间及时区、换日约定；原问题的对象与期限。
3. **卦象：** 先将程序返回的 `text_diagram` 原样放入 `text` 代码块，展示本卦与变卦的字符卦图；静卦仅画本卦。保留六爻顺序、阴阳断线、动爻标记与世应，不凭卦名自行拼图。随后按需列卦宫、动爻及上→下的详细六爻表；六神、伏神、世应和动爻化出列依程序填写。
4. **分析：** 用神取舍、日月和动变依据、关键支持与阻碍。解释术语，不要求用户懂全部专业词。
5. **关键变数（可选）：** 只写会改变主判断、且有依据的具体条件。用户需要时再给现实建议，不固定附加核查清单。

通常用“按此卦”“卦理上倾向”标明解读性质即可，不固定插入免责声明或在结尾撤回主结论。涉及健康、法律或财务时，不把卦象包装为诊断或决策依据，不给停止治疗等建议。

用户只要求排盘时，交付卦盘即可。用户要求保存完整分析时，在输出目录另写 `analysis.md`，保留原始 `input.json` 和 `chart.json`，不要事后修改输入来贴合反馈。
